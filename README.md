# Mango Balance

**Манго Баланс** — приложение на Flutter для учёта личных финансов. Помогает отслеживать доходы и расходы, планировать бюджет и видеть, как меняется общий баланс. Работает локально: без регистрации, сервера и подключения к банкам; данные хранятся в SQLite на устройстве. Интерфейс — на русском языке.

## Возможности

- Счета с начальным балансом, доходы, расходы и переводы между счетами.
- Категории операций, фильтры по счёту, типу и датам.
- Несколько независимых профилей, например для личных и семейных финансов.
- Статистика по категориям и периодам, график общего баланса, бюджеты с лимитами расходов.
- Регулярные доходы и расходы с локальными напоминаниями.
- Импорт и экспорт XLSX, резервное копирование и восстановление профилей вместе со счетами, операциями, бюджетами и регулярными платежами.

## Платформы и ограничения

В репозитории настроены Android, iOS, macOS, Windows и Linux. Для сборки нужны инструменты соответствующей платформы. Веб-версия пока не поддерживается: база данных использует `dart:io` и нативный SQLite.

Напоминания реализованы для Android, iOS и macOS и требуют разрешения на уведомления. Регулярные операции добавляются при запуске приложения, смене профиля и изменении регулярных платежей; отдельного фонового сервиса для их создания нет. Облачной синхронизации между устройствами нет — данные можно перенести через XLSX.

## Запуск из исходников

Нужны Git, [Flutter SDK](https://docs.flutter.dev/install) в `PATH` и настроенное окружение целевой платформы: например, Android SDK и эмулятор или устройство для Android; Xcode на macOS для iOS/macOS.

Текущий `pubspec.lock` требует **Flutter ≥ 3.35.6 и Dart ≥ 3.9.0, < 4.0.0**. Dart входит в Flutter SDK. Сохраняйте версии зависимостей из lock-файла для воспроизводимой установки.

```bash
git clone https://github.com/ymnavfka/mango_balance.git
cd mango_balance
flutter doctor
flutter pub get
flutter devices
flutter run -d <device_id>
```

Замените `<device_id>` идентификатором из `flutter devices`. Сервер, API-ключи и `.env` не нужны; база создаётся при первом запуске. Сгенерированный код Drift уже включён в репозиторий.

Чтобы познакомиться с приложением на примере заполненных профилей:

```bash
dart run tool/gen_demo_backup.dart demo_data.xlsx
```

Откройте импорт XLSX в меню приложения и выберите полученный файл. Демо содержит операции за фиксированный период до 10 августа 2026 года — выберите этот период в статистике.

### Сборка Android APK

Для тестирования на Redmi Note 13 используйте отдельный ARM64 APK:

```bash
flutter build apk --release --target-platform android-arm64 --split-per-abi
```

Результат: `build/app/outputs/flutter-apk/app-arm64-v8a-release.apk` (около 23 МБ). Для обновлений сохраняйте этот формат сборки и тот же ключ подписи. У ARM64-сборки с `--split-per-abi` код версии отличается от универсального APK: при текущем `1.0.0+6` это `2006` вместо `6`. Универсальный APK с меньшим кодом версии не подходит для обновления ранее установленной ARM64-сборки.

Универсальный APK для нескольких архитектур (около 66 МБ):

```bash
flutter build apk --release
```

Результат: `build/app/outputs/flutter-apk/app-release.apk`. Без `android/key.properties` сборка использует отладочный ключ; для публикации нужна собственная релизная подпись. Настройка находится в [android/app/build.gradle.kts](android/app/build.gradle.kts).

## Как устроен код

Проект организован по функциональным модулям в [lib/features/](lib/features/): счета, категории, операции, профили, статистика, бюджеты, регулярные платежи, импорт и экспорт. Внутри модулей три слоя:

- `presentation/` — экраны, виджеты и состояние на **Cubit / flutter_bloc**.
- `domain/` — сущности, сценарии использования и интерфейсы репозиториев.
- `data/` — реализации репозиториев, работа с БД и файлами.

**Drift / SQLite** отвечает за хранение и потоки данных, **get_it** — за внедрение зависимостей, **fl_chart** — за графики, **excel** — за XLSX. Изменения в БД поступают через репозитории и сценарии использования в Cubit, после чего обновляется интерфейс.

Точки входа для чтения кода:

| Файл или каталог | Что искать |
| --- | --- |
| [lib/main.dart](lib/main.dart) | Запуск приложения, провайдеры состояния и маршруты |
| [lib/core/di/injector.dart](lib/core/di/injector.dart) | Регистрация зависимостей |
| [lib/core/database/app_database.dart](lib/core/database/app_database.dart) | Схема SQLite, миграции и запросы |
| [lib/features/transactions/](lib/features/transactions/) | Пример полного модуля: от формы операции до сохранения |
| [lib/core/services/notification_service.dart](lib/core/services/notification_service.dart) | Разрешения и планирование уведомлений |
| [lib/features/shared/](lib/features/shared/) | Общие виджеты, тема и утилиты интерфейса |

## Разработка

После изменения схемы или запросов Drift перегенерируйте код:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Проверки из корня проекта:

```bash
flutter analyze
flutter test
```

Текущие [тесты](test/) проверяют сервис уведомлений, связанные с ним сценарии Cubit и виджеты регулярных платежей. Остальные модули пока не покрыты автоматическими тестами.

Ошибки и предложения можно описать в [Issues](https://github.com/ymnavfka/mango_balance/issues). Для воспроизведения укажите платформу, версию Flutter и последовательность действий.
